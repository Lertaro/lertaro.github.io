인덱싱 관리 ​

인덱스 설정 페이지에서는 로컬 드라이브, 네트워크 공유, WSL 및 사용자 지정 폴더에 대한 인덱싱 범위, 갱신 주기 및 제외 규칙을 정밀하게 제어합니다. 상단에는 로컬 드라이브, 네트워크 드라이브, WSL(배포판 감지 시에만 표시), 폴더, 제외 규칙의 5개 탭이 제공됩니다.

1. 로컬 드라이브 (Local Drives) ​

  • 상단 요약 카드: 현재 인덱싱된 물리 드라이브 수와 총 파일/폴더 수를 보여주며, 전체 재구축을 실행하는 인덱스 재구축 버튼을 제공합니다.
  • 드라이브 목록 행:
    • 활성화 체크박스: 파티션별 인덱싱을 독립적으로 토글.
    • 파일 시스템 및 상태: 파일 시스템 종류(NTFS, ReFS, FAT32, exFAT 등), 상태 및 인덱싱된 항목 수 표시.
    • 개별 조작: 재구축 및 제거 버튼. 스캔 진행 중에는 중지 버튼이 동적으로 나타납니다.
  • 실시간 감지: NTFS / ReFS 볼륨은 Windows USN 변경 저널을 읽어 밀리초 단위로 동기화하며, FAT32 / exFAT는 파일 변경 이벤트를 실시간 감지합니다.
  • 중단 없는 재구축: 드라이브를 재구축하는 동안에도 새 인덱스가 완성될 때까지 기존 인덱스가 검색에 계속 응답하므로 검색이 중단되지 않습니다. 중단되더라도 다음 실행 시 중단점부터 재개됩니다.

2. 네트워크 드라이브 (Network Drives) ​

  • 네트워크 공유 지원: 매핑된 Windows 네트워크 드라이브(SMB / NAS) 목록 표시.
  • 새로고침 모드 (Refresh Mode): 로컬 저널이 없으므로 정기 스캔 주기를 설정:
    • 수동 —— "인덱스 재구축" 클릭 시에만 스캔.
    • 15분마다 —— 공동 작업용 공유 폴더 추천.
    • 매시간 —— 균형 잡힌 정기 스캔.
    • 매일 —— 보관용 공유 폴더 추천.
  • 심볼릭 링크 순환 보호: NAS 상의 재귀 심볼릭 링크나 정션으로 인한 무한 루프를 방지하기 위해 순환 감지 알고리즘이 중복 경로를 자동 건너뜁니다.

3. WSL (Linux용 Windows 하위 시스템) ​

WSL 배포판이 설치되어 있는 경우에만 자동으로 나타납니다.

  • 자동 감지: Ubuntu, Debian, Arch 등 설치된 WSL 배포판 자동 인식.
  • 상태 및 스케줄: 네트워크 드라이브와 동일한 상태 관리 및 새로고침 모드(수동 / 15분 / 매시간 / 매일) 제공.
  • 제로 I/O 검색: WSL 파일 검색 시 메모리 인덱스를 직접 쿼리하여 Linux 서브시스템에 부하를 주지 않습니다.

4. 폴더 (Folders) ​

드라이브 전체가 아닌 특정 작업 폴더만 인덱싱하고 싶을 때 사용합니다.

  • 다중 선택 추가: 폴더 추가를 클릭하고 Ctrl이나 Shift를 누른 채 여러 폴더를 일괄 선택하여 추가할 수 있습니다.
  • UNC 경로 지원: \\server\share\projects와 같은 네트워크 UNC 경로도 직접 등록 가능합니다.
  • 개별 스케줄 설정: 각 폴더마다 독립적인 활성화 스위치, 항목 카운터 및 새로고침 모드 드롭다운이 제공됩니다.

5. 제외 규칙 (Exclusions) ​

제외 규칙은 검색 결과를 걸러내고 네트워크, WSL, 폴더 인덱스의 탐색 범위를 제한합니다. 로컬 드라이브의 인덱싱은 중단하지 않습니다. 로컬 볼륨은 항상 전체가 탐색되므로 여기에 E:\를 적어도 결과만 숨겨집니다. 로컬 드라이브의 인덱싱을 중단하려면 위의 로컬 드라이브 탭에서 끄세요. 규칙은 하위 탭 없이 하나의 목록으로 정리됩니다. 각 규칙은 일치 방식과 단계의 조합이고, 일치 방식은 입력 모양에서 자동으로 판정되며 입력창에 인식: 으로 표시됩니다.

  • 전체 경로: 드라이브 문자(D:\Cache), UNC(\\server\share), 환경 변수(%ProgramData%, %APPDATA%), shell: 가상 경로로 시작합니다. 해당 폴더와 그 아래 모든 항목을 가립니다.
  • 와일드카드: 그 밖의 입력은 모두 와일드카드입니다. *는 한 계층 내 임의 문자(*.log), ?는 문자 하나, **는 하위 계층 전체(**\node_modules\**)와 일치합니다. 구분 기호가 없는 규칙은 이름으로 아무 깊이에서 일치하고(node_modules, *.tmp), 구분 기호가 있는 규칙은 드라이브 맨 위에서부터 고정됩니다. 따라서 Listary\abc는 C:\Listary\abc와 그 아래 항목에 일치하지만 D:\work\Listary\abc에는 일치하지 않습니다.
  • 정규식: 슬래시로 감쌉니다. 예를 들어 /^\./는 점으로 시작하는 숨김 파일, /~\$/는 Office 임시 잠금 파일입니다. 전체 경로와 파일 이름에 대해 부분 일치로 평가됩니다. 와일드카드로 충분하면 정규식을 쓰지 마세요. 정규식은 일치할 때마다 해석 실행을 해야 해서 더 비쌉니다.

단계는 처리 방식을 정합니다. 제외는 표시하지 않고, 낮음·보통·높음은 순서만 바꿉니다. 높음 규칙은 체크로 최상단에 고정할 수 있습니다. 단계는 행 오른쪽 드롭다운에서 고르거나 텍스트 앞 접두사로 적을 수 있습니다: ! 제외, - 낮음, + 높음, 없으면 보통. 줄 맨 앞의 백슬래시는 접두사를 글자로 처리합니다.

NOTE

접두사는 추가 입력창과 일괄 편집에서만 제거됩니다. 기존 규칙을 행 안에서 편집할 때는 텍스트를 글자 그대로 다루므로 단계는 드롭다운으로 바꾸세요. 와일드카드 규칙에 남은 !는 경로의 글자가 되고, Windows 경로에는 !가 없으므로 그 규칙은 아무것도 일치하지 않습니다. 화면에서 오류도 나타나지 않습니다.

로컬 디스크는 검색할 때 적용하고, 네트워크 디스크·WSL·사용자 지정 폴더는 인덱스를 만들 때 제외 항목을 건너뛰며 설정을 적용한 뒤 새로 고칩니다. 제외 규칙이 우선순위 규칙을 덮으면 목록 위에 충돌 배너가 뜨고, 덮인 규칙은 적용되지 않습니다.

TIP

규칙은 개별 추가 및 텍스트 일괄 가져오기/내보내기를 모두 지원합니다. 목록에서 생성을 눌러 내보내고, 편집 후 목록에 적용을 눌러 일괄 갱신할 수 있습니다. 일괄 텍스트에 인식할 수 없는 줄이 하나라도 있으면 아무 줄도 적용되지 않고, 텍스트는 수정을 기다리며 창에 남습니다.
