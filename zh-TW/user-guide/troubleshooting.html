疑難排解 ​

在使用 Lertaro 的過程中遇到問題？請按照以下步驟逐步排查常見故障原因。

1. 全域快速鍵沒有反應 ​

  • 檢查背景服務執行狀態：進入設定 → 執行狀態，確認背景索引服務（服務名稱 LertaroService）處於「執行中」。雖然普通快速鍵由 App 處理，但提權攔截處理程序依賴背景服務拉起。
  • 系統管理員權限隔離（UIPI）：若目前前景活動視窗是以系統管理員身分執行的（例如以系統管理員開啟的終端機或工作管理員），Windows 系統的安全機制（UIPI）會阻止低權限處理程序向高權限視窗傳送快速鍵。Lertaro 會自動嘗試提權快速鍵攔截處理程序；若仍無回應，請確保背景服務處於正常執行狀態。
  • 檢查處理程序黑名單：在設定 → 快速鍵中檢查目前前景程式是否被列入了「處理程序黑名單」。處於黑名單中的程式在前景時，Lertaro 會主動放行按鍵不做攔截。
  • 全螢幕遊戲/獨占應用程式放行：當偵測到前景有獨占全螢幕執行的應用程式（如 3D 遊戲、全螢幕播放器）時，Lertaro 預設會自動放行快速鍵以防干擾操作。如果你希望在全螢幕下依然能夠呼出搜尋框，請在設定 → 快速鍵中勾選全螢幕應用程式聚焦時仍然回應。

2. 搜尋結果未更新或過時 ​

  • 本機 NTFS / ReFS 磁碟：Lertaro 透過讀取底層 USN 變更記錄檔實現近乎零延遲的毫秒級即時更新。
  • FAT32 / exFAT 磁碟：透過系統檔案變更事件持續監聽。
  • 手動重建索引：若由於系統意外斷電等原因導致索引不一致，請前往設定 → 索引 → 本機磁碟機，在對應的磁碟上按一下重建索引即可重新產生乾淨的記憶體索引。

3. 網路磁碟機未自動重新整理 ​

  • 定時掃描機制：網路共用（SMB / NAS）沒有本機 NTFS 卷的底層變更記錄檔，因此依賴定時輪詢機制。
  • 檢查重新整理模式：在設定 → 索引 → 網路磁碟機中檢查該磁碟機的重新整理模式是否被誤設為了「手動」；若設為手動，必須按一下「重建索引」或改為定時重新整理。
  • 符號連結環路保護：對於 NAS 共用中可能存在的遞迴符號連結，Lertaro 內建了環路偵測引擎，會自動略過死循環目錄。

4. 某個檔案或資料夾完全搜尋不到 ​

  • 檢查排除規則：進入設定 → 索引 → 排除規則，確認目標檔案路徑是否被精確路徑、Glob 萬用字元或規則運算式規則意外命中。
  • 檢查磁碟啟用狀態：在設定 → 索引 → 本機磁碟機中確認該檔案所在的實體磁碟機或目錄是否處於開啟狀態。

5. 內嵌視窗中中文輸入法候選字浮動視窗未彈出 ​

  • 無焦點設計原理：內嵌視窗為了在關閉後將焦點歸還給宿主軟體，特意採用了無焦點設計。輸入法候選字浮動視窗依賴 Windows 真實鍵盤焦點，因此在內聯視窗中可能不顯示候選浮動視窗。
  • 推薦解決方案：
    1. 直接打拼音：Lertaro 內建了拼音別名引擎，直接輸入拼音字母即可跳躍命中中文檔案名稱（詳見搜尋語法），無需呼叫輸入法候選字浮動視窗。
    2. 切換為快速視窗：按下按兩下 Ctrl 喚出擁有完整焦點的快速視窗，即可正常使用任何輸入法。

6. 記錄檢視與提交 Issue ​

若上述步驟均未能解決你的問題，請進入設定 → 執行狀態檢視詳細的執行記錄：

  • Service 記錄：記錄背景索引服務、USN 記錄檔讀取、網路磁碟掃描與 IPC 通訊狀態。
  • App 記錄：記錄前景 UI 轉譯、外掛模組載入、快速鍵回應與設定變動。
  • Hook 記錄：記錄全域鍵盤鉤子與滑鼠導覽手勢的事件串流。

你可以在記錄面板中使用搜尋框過濾關鍵字，或按記錄等級（Info / Warn / Error）快速定位異常堆疊，並在 GitHub 提交 Issue 時附上相關記錄以便快速定位。
