索引 ​

按顺序共五个 Tab：本地驱动器、网络驱动器、WSL（只在检测到发行版时才出现）、文件夹、排除规则。

本地驱动器 ​

  • 顶部状态卡片汇总已索引的驱动器数量与项目数量，并提供重建索引按钮做全量重扫描。
  • 每个本地驱动器一行：启用/禁用复选框、驱动器名称、文件系统（NTFS/ReFS 等）、当前状态、已索引项目数，以及每行独立的重建/移除操作——重建进行中时还会出现停止操作（真正的 NTFS 走 $MFT 扫描没有安全的中断点，是唯一的例外）。
  • NTFS 和 ReFS 磁盘通过 Windows USN 日志持续跟踪变更；其他本地文件系统（FAT32、exFAT 等）没有日志可读，改为直接监听文件系统变化。不管哪种方式，手动重建都很少需要，但如果发现内容不同步，随时可以用它——如果重建过程中被中断（手动停止，或者应用/服务中途重启），下次会从中断的地方继续，而不是从头再来。

重建期间搜索照常可用。正在重建的驱动器会继续用它此前的索引应答，直到新索引就绪；其余驱动器完全不受影响——重建不会让你面对一个空的结果列表。

网络驱动器 ​

  • 与本地驱动器相同的状态卡片和重建索引按钮。
  • 每个已映射的网络驱动器一行：启用复选框、路径/名称、状态（索引中 / 就绪 / 已缓存 / 失败 / 等待中 / 已连接）、项目数，以及刷新模式下拉框：
    • 手动 —— 只在手动触发（重建索引）时刷新。
    • 每 15 分钟
    • 每小时
    • 每天

网络共享没有本地 NTFS 卷那样的变更日志可供监听，所以采用定时刷新而不是实时更新。扫描引擎内置了分支祖先路径栈与符号链接环路检测机制，即使 NAS/SMB 共享上存在指向父级目录的软链接或重解析点，也能自动拦截死循环，确保索引数量准确不膨胀。

WSL ​

只有检测到至少一个 WSL 发行版时才会出现——形态和网络驱动器一样（状态卡片、重建索引按钮，每个发行版一行，显示状态/项目数/刷新模式）。发行版是自动检测的，没有手动“添加”这一步。

文件夹 ​

单独索引任意文件夹，而不是整个驱动器或共享——适合只想索引某一个子目录，而不想把这个盘/共享下的其他内容也纳入索引的场景。

  • 添加文件夹按钮会打开文件夹选择器；重建索引按钮会重新扫描列表中的所有文件夹。
  • 每个已添加的文件夹一行：启用复选框、路径、状态、项目数，以及和网络驱动器一样的刷新模式下拉框（手动 / 每 15 分钟 / 每小时 / 每天）——文件夹和网络共享一样按计划扫描，而不是持续实时跟踪。
  • 文件夹选择器也支持直接选一个 UNC 网络共享路径（比如 \\server\share，或者它里面的子目录）——在选择器里通过“网络”浏览过去即可，适合只想索引某一个共享或子目录，而不想把整台服务器都加成映射的网络驱动器。

排除规则 ​

三个子 Tab，形态完全一致：一个单条输入框 + 添加按钮，一个可编辑/删除每一条规则的列表，以及一个批量多行文本框，配 从列表生成 / 应用到列表 两个按钮，用来一次性编辑全部规则。

  • 路径排除 —— 完整路径或环境变量（例如 D:\Cache、%ProgramData%）。
  • Glob 通配符 —— *（文件名中任意字符）、?（单个字符）、**（递归目录）。示例：*.tmp、**/node_modules/**、bin/**。
  • 正则表达式 —— 针对路径/文件名做部分匹配的任意正则。示例：^\.（隐藏文件）、~$（Office 临时文件）、\.git\。

排除规则对本地、网络、文件夹索引都生效，应用排除规则的改动后，网络驱动器/文件夹会自动重新扫描。
